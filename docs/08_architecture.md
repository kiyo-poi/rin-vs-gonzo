# 08 設計（アーキテクチャ）

実装の骨組みを決める。コードはまだ書かない。型や JSON は「データの形」を示す例で、名前や細部は実装時に変わってよい。
ルールや数値そのものは 01〜06 が正で、この文書は「それをどう組むか」を書く。

- 「推奨（ユーザー未確定）」と書いた項目は、設計側で仮に決めたもの。`open-questions.md` の「設計（08_architecture.md）」にも載せてある
- 画像・音の作り方やファイル命名は `07_assets.md`、作る順番は `09_roadmap.md` に任せる

## 1. 技術構成

| 項目 | 採用 | 理由 |
|---|---|---|
| 言語 | TypeScript（strict） | 技データの書き間違いを型で防げる |
| 描画 | Canvas 2D（1枚） | `04_system.md` の決定どおり。ゲーム用ライブラリは使わない |
| ビルド | Vite | 設定がほぼ不要で起動が速い。保存すると即反映されるので数値調整が楽。`vite build` で静的ファイルが出るので GitHub Pages / Cloudflare Pages にそのまま置ける。フォルダ内のキャラデータを自動で集める機能（`import.meta.glob`）が「コードを変えずにキャラ追加」に使える |
| テスト | Vitest | Vite と同じ設定で動くので追加設定がいらない。対戦ロジックのフレーム単位テストに使う |
| 音 | Web Audio API（ブラウザ標準） | 効果音の同時再生と遅延の少なさのため。`<audio>` 要素は使わない |

- 依存は開発用の `typescript`・`vite`・`vitest` の3つだけ。ゲーム本体が読み込む外部ライブラリはゼロ
- Lint・フォーマッタは入れない（必要になったら追加）
- 公開：`vite build` の出力（`dist/`）を置くだけ。`base: './'`（相対パス）にして、GitHub Pages のサブパスでも Cloudflare Pages のルートでも同じ出力で動くようにする

## 2. 全体の構成

```
            キーボード ──→ 入力 ──→ ┐
                                  ├→ 各プレイヤーのボタン状態（1F分）
            CPU（同じ形で出力）──→ ┘            │
                                               ▼
  ゲームループ（60F固定）──→ シーン ──→ 対戦ロジック（純粋な処理）
                                               │ 状態 ＋ 出来事（ヒットした等）
                                               ▼
                                   描画（カメラ・キャラ・HUD・演出）／ 音
```

- 対戦ロジックは「前のフレームの状態」と「このフレームの入力」から「次の状態」と「出来事の一覧」を作るだけ
- 描画と音は状態と出来事を読むだけで、ロジックに書き戻さない

### 2.1 ゲームループ

- `requestAnimationFrame` で毎回呼ばれ、経過時間を貯めて 1/60 秒ぶんごとに「更新」を1回行う（固定ステップ）。描画は貯めた分の更新が終わったあと1回だけ
- モニターが 120Hz でも 60Hz でも、ゲームの進み方は同じ（更新回数は常に1秒60回）
- 1回の呼び出しで行う更新は最大 4 回まで。タブを裏に回して戻ったときなどに一気に何百フレームも進むのを防ぐ（あふれた時間は捨てる）
- 描画はロジックの最新状態をそのまま描く（フレーム間の補間はしない。60F単位のゲームなので不要）
- ヒットストップ・超必殺の暗転・KO のスローは「ループの速さ」ではなく対戦ロジック側のフレームカウンタで表す。ループは常に60Fで回る

### 2.2 シーン管理

| シーン | 役割 |
|---|---|
| タイトル | ロゴとキー配置。最初のキー入力で音を使えるようにする（ブラウザの自動再生制限のため） |
| モード選択 | 2人対戦 / CPU戦、CPU戦なら難易度 |
| キャラ選択 | 1P・2P 同時選択。キャラデータから選択肢を並べる |
| 対戦 | 対戦ロジックを動かし、描画・音・HUD を出す |
| 結果 | 勝者表示と「再戦 / キャラ選択へ / タイトルへ」 |
| ポーズ | 対戦の上に重ねて表示する |

- シーンは「積み重ね（スタック）」で持つ。ポーズは対戦シーンの上に積み、ポーズ中は下の対戦シーンを「描くだけで更新しない」
- シーン同士の受け渡し（選んだモード・難易度・キャラ）は「対戦の設定」1つのオブジェクトにまとめて渡す。再戦はこの設定をそのまま使う
- 各シーンは `更新(入力)`・`描画(画面)`・`入る`・`出る` の4つを持つ
- 画面の切り替えは短い暗転（フェード）を挟む。フェード中は入力を受け付けない
- 対戦中にブラウザのウィンドウからフォーカスが外れたら自動でポーズにする（推奨（ユーザー未確定））。キーを押したまま別ウィンドウに移ると、離した操作が届かずキーが押しっぱなし扱いになるため。同時に押下中のキーをすべて離した扱いにする

### 2.3 入力

**キー → ボタン**

- キーは `KeyboardEvent.code`（物理的なキーの位置。`KeyA`、`Numpad4`、`ArrowLeft` など）で判定する。日本語入力の状態や NumLock の有無に左右されない
- キー配置は設定データ（`src/data/controls.json`）に置く。1つのボタンに複数のキーを割り当てられる形にし、2P のパンチは `Numpad4` と `KeyJ` のどちらでも反応する（どちらか押されていれば押している扱い）

```json
{
  "p1": { "left": ["KeyA"], "right": ["KeyD"], "up": ["KeyW"], "down": ["KeyS"],
          "punch": ["KeyF"], "kick": ["KeyG"], "grab": ["KeyH"], "special": ["KeyV"], "guard": ["KeyB"] },
  "p2": { "left": ["ArrowLeft"], "right": ["ArrowRight"], "up": ["ArrowUp"], "down": ["ArrowDown"],
          "punch": ["Numpad4", "KeyJ"], "kick": ["Numpad5", "KeyK"], "grab": ["Numpad6", "KeyL"],
          "special": ["Numpad1", "KeyM"], "guard": ["Numpad2", "Comma"] },
  "pause": ["Escape"]
}
```

- ゲームで使うキーはブラウザの既定動作（矢印キーでのスクロールなど）を止める
- キーの押下・解放はイベントで「今押されているキー」の集合に記録するだけ。ゲームはフレームの頭でその集合を1回読み取り、そのフレームの「ボタン状態」を作る（フレームの途中で入力が変わらない）

**ボタン状態（1F分）**

```ts
type Button = 'left' | 'right' | 'up' | 'down' | 'punch' | 'kick' | 'grab' | 'special' | 'guard';

interface InputFrame {
  held: Record<Button, boolean>;     // このフレームに押されているか
  pressed: Record<Button, boolean>;  // このフレームに押されたか（前フレームは離れていた）
}
```

- 対戦ロジックは `InputFrame` だけを受け取る。キーボードか CPU かを区別しない
- 左右は「前・後ろ」に変換してから使う（向きによって入れ替える）。左右同時押しはどちらも押していない扱い

**入力バッファ（先行入力）**

- 攻撃ボタン（パンチ・キック・掴み・必殺）が押されたら、そのとき押していた方向と一緒に 6F の間覚えておく（推奨（ユーザー未確定））
- 硬直・のけぞり・ガード硬直・ヒットストップ中に押した攻撃は、動けるようになった最初のフレームに覚えていた分から出す。キャンセルの受付も同じバッファを見る
- 必殺技の向き（ニュートラル / → / ↓）は「ボタンを押したフレームの方向」で決める（出るフレームの方向ではない）
- 同じフレームに複数の攻撃ボタンがあるときの優先順位：超必殺 ＞ 必殺 ＞ 掴み ＞ キック ＞ パンチ。方向は ↓ を → より優先する（↓→ 同時なら ↓＋必殺）

**超必殺（必殺＋ガード同時押し）の受付**

- 必殺とガードの「押した瞬間」が 3F 以内なら同時押しとみなす（推奨（ユーザー未確定））。どちらが先でもよい
- 必殺を先に押した場合、必殺技はすぐ出始める。3F 以内にガードが押されたら、出始めの必殺技を超必殺に差し替える（必殺技の出が遅れないようにするため）
- ガードを押しっぱなしの状態で必殺を押しても、ガードを押した瞬間が 3F より前なら同時押しではない（ガードしながら必殺を押すと通常の必殺技が出る）
- ゲージが満タンでなければ同時押しでも超必殺にならず、通常の必殺技（方向に応じた3種）が出る
- 空中では超必殺も必殺も出ない（入力は捨てる）

**2P の両系統**

- テンキー系と J〜, 系は「同じボタンのキーが複数ある」だけなので、混ぜて押してもよい（例：パンチはテンキー4、キックは K）
- メニューは 1P・2P どちらのボタンでも操作できるシーンと、各自のボタンだけを見るシーン（キャラ選択）がある（`05_screens.md`）。シーンが必要な側の `InputFrame` を読むだけで、入力部分は区別しない

### 2.4 対戦ロジック

**キャラの状態**

| 状態 | 内容 | 次の状態へ |
|---|---|---|
| 待機 / 歩き前 / 歩き後ろ / しゃがみ | 自由に動ける | 入力しだい |
| ガード | ガードボタンを押している間。立ち・しゃがみとも同じ。歩けない | ボタンを離す / 攻撃入力 |
| ジャンプ（踏み込み） | 地上扱いの準備動作 | 空中へ |
| 空中 | 放物線で移動。空中攻撃は1回だけ | 着地 → 着地の隙 → 待機 |
| 技 | 発生 → 持続 → 硬直 | 全体フレームが終わったら待機 |
| のけぞり / ガード硬直 | 動けない | 時間が切れたら待機 |
| 空中やられ | 空中で食らって落ちている | 着地でダウン |
| ダウン → 起き上がり | 起き上がりの瞬間は無敵 | 待機 |
| 掴まれ / 投げ中 | 投げの演出中。投げ抜けの受付あり | 投げ終わり → ダウン（掴まれた側） |
| 弾かれ | 相打ち・投げ抜けのあと | 時間が切れたら待機 |
| KO / 勝利 / ラウンド開始待ち | 操作を受け付けない | ラウンドの進行しだい |

- 状態は「名前」と「その状態に入ってからのフレーム数」で持つ。技中なら「どの技か」も持つ
- 振り向きは「待機・歩き・しゃがみ・ガード・着地の瞬間・技やのけぞりが終わった瞬間」にだけ行う（`04_system.md`）

**1フレームの処理順**

対戦ロジックの更新は毎フレーム次の順で行う。順番を固定するのは「何フレーム目に何が起きるか」をテストで確かめられるようにするため。

1. **止まっているか確認**：ラウンド開始表示中・暗転中・ヒットストップ中は、カウンタを1減らして入力をバッファに貯めるだけで終わる
2. **入力を読む**：両者の `InputFrame` をバッファに足す
3. **行動を決める**：動ける状態なら、バッファから技・ジャンプ・ガード・歩きを決める。技中ならキャンセルできるか見る
4. **動かす**：歩き・ジャンプ・技の突進を位置に足す
5. **押し合い**：押し合いの箱の重なりを解消し、ステージの端と2人の最大距離に収める
6. **向きを更新**
7. **判定を集める**：両者の攻撃・掴みが相手に届いたかを、両方とも「動かしたあとの同じ位置」で調べる。片方を先に処理しない（1P が有利にならない）
8. **結果を決める**：下の「判定の優先順位」で、ヒット・ガード・相打ち・投げ・アーマーを決める
9. **結果を反映**：ダメージ・のけぞり・ノックバック・ゲージ・連続技の数・ヒットストップ
10. **時間と勝敗**：タイマーを進め、KO・時間切れを判定する
11. **出来事を出す**：「ヒットした」「ガードされた」「相打ち」「投げ抜け」「超必殺開始」「KO」などを一覧にして返す。描画・音・HUD はこれを見て演出する

**判定の箱**

| 箱 | 役割 | 持たせる場所 |
|---|---|---|
| 押し合い | キャラ同士が重ならないための箱。1つだけ | キャラの立ち・しゃがみ・空中ごと |
| 食らい | 攻撃を受ける範囲。複数可 | キャラの立ち・しゃがみ・空中ごと。技ごとに上書きできる（下段掌で姿勢を低くするなど） |
| 攻撃 | 当たると相手にダメージ | 技の持続中だけ |
| 掴み | 掴み間合いの中なら掴める | 掴み・コマンド投げの持続中だけ |

- 箱はすべて四角（長方形）。円や傾いた形は使わない
- 座標は「キャラの足元の中心」を原点、右向き基準、上がプラス（px）。左向きのときは左右を反転して使う
- 掴み間合いは「自分の押し合いの箱の前の端」から「相手の押し合いの箱の前の端」までの隙間で測る（推奨（ユーザー未確定））。キャラの横幅の違いで間合いが変わらないようにするため。`06_params.md` の掴み間合い（60px など）はこの隙間の上限

**判定の優先順位**

同じフレームで起きたことは、次の順番で決める。上の項目で決まったら下は見ない。

1. **無敵**：無敵中の相手には攻撃も掴みも当たらない（起き上がりの無敵は掴みも防ぐ）
2. **掴めない状態**：空中・のけぞり中・ガード硬直中・ダウン中の相手は掴めない。ジャンプの踏み込み中は地上扱いなので掴める（推奨（ユーザー未確定））
3. **両者の攻撃が同時に届いた**
   - 打撃 対 打撃 → 相打ち。両者弾かれてダメージなし（同じフレームのときだけ。1F でもずれたら先に当てた方の勝ち）
   - 片方が超必殺 → 超必殺が一方的に勝つ。超必殺同士 → 相打ち（ゲージは戻らない）
   - 片方がアーマー中（耐えられる回数が残っている） → 相打ちにせず、アーマー側が耐えて、アーマー側の攻撃が当たる（推奨（ユーザー未確定））
   - 打撃 対 掴み → 打撃が勝つ（三すくみ）
   - 掴み 対 掴み → 両者弾かれる（投げ抜けと同じ扱い）（推奨（ユーザー未確定））
4. **掴み**：掴めたら「掴まれ」状態へ。投げ抜けできる掴みは、掴まれた側が 8F 以内に掴みを押すと両者弾かれる。コマンド投げ（ジャイアントスイング）は投げ抜けなし。掴みはガードもアーマーも無視する
5. **アーマー**：打撃をアーマーで耐えたら、のけぞらず、ダメージは `06_params.md` の割合だけ受ける。ヒットストップはかかる。超必殺はアーマーを無視して当たる（推奨（ユーザー未確定））
6. **ガード**：ガード状態（またはガード硬直中）なら打撃をガードする。空中ではガードできない（推奨（ユーザー未確定））
7. **ヒット**：ダメージ・のけぞり・ノックバック。空中の相手に当たったら「空中やられ」で落下し、着地でダウン。落下中は追撃できない（推奨（ユーザー未確定））

**多段ヒット**

- 技の攻撃は「1発ごとの当たり」のリストで持つ（連拳なら5つ）。1つの当たりは、持続の間に相手1人へ1回だけ当たる
- 連拳のように「1発ガードしたら最後までガード」の技は、技データに「ガード固定」の印を付ける。最初の1発がガードされたら、その技の残りの当たりはすべてガード扱いにする
- 1発目が外れて2発目から当たった場合も、そこからは普通に当たる

**連続技とダメージ補正**

- 相手がのけぞっている間に次の技が当たったら連続技。相手側に「連続技の技数」と「ヒット数」を持つ
- ダメージ補正は「技数」が2以上のとき（キャンセルや繋ぎで2つ目の技が当たったとき）にかける。同じ技の多段ヒット同士では補正しない（`03_moves.md`）
- HUD の「2 HIT」はヒット数を表示する
- のけぞりが終わって動けるようになったら両方0に戻す

**キャンセル**

- 通常技（立ち・しゃがみのパンチ・キック）の攻撃がヒットまたはガードされたら、そのフレームから硬直の最後まで必殺技（3種）の入力を受け付ける。空振りではキャンセルできない
- 通常技 → 超必殺のキャンセルはなし（推奨（ユーザー未確定））。必殺技 → 超必殺もなし（`04_system.md`）
- 受付はヒットストップ中も含む（ヒットストップ中に押した入力はバッファに入り、明けた最初のフレームで出る）

**削り・ゲージ・ノックバック**

- 削り：必殺技・超必殺がガードされたら本来のダメージ × 削り割合。通常の必殺技は削りで体力1未満にしない。超必殺だけ削りで KO できる
- ダメージ・削り・ゲージ増加の端数は切り捨て（整数で持つ）
- ゲージは 0〜1000 の整数。超必殺の暗転の開始で0にする
- ノックバック：ヒット・ガードで相手を後ろへ押す。相手が画面端で下がれない分は攻撃側が下がる

**超必殺の暗転**

- 超必殺が出たら、技の1フレーム目より前に暗転（全体停止）を入れる。技の発生・無敵のフレームは暗転のあとから数える（`06_params.md` の「暗転後に無敵をどこまで付けるか」と合わせる）
- 暗転中は相手も止まる。暗転中に押した入力はバッファに入る

**タイマー**

- 99秒＝5940F をフレームで数える。HUD は残りフレームを60で割って切り上げた数を表示
- ラウンド開始表示・ヒットストップ・暗転・投げ演出・KO後は止める（推奨（ユーザー未確定））

**ラウンドの進行**

- ラウンド開始表示 → 対戦 → 決着（KO / 時間切れ / 引き分け）→ 次のラウンドか試合終了、を対戦ロジックの中で持つ
- 同時 KO（同じフレームで両者の体力が0）は両者に1勝（`01_concept.md`）
- 試合が決まったら「試合終了」の出来事を出し、対戦シーンが結果シーンへ移る

**乱数**

- ロジックの中では `Math.random()` や現在時刻を使わない。対戦開始時に決めた種（シード）から作る乱数だけを使う。同じ入力なら必ず同じ結果になる

### 2.5 カメラ

- 横位置は2人の中間。ステージ（0〜1920px）の外は映さないように止める。縦は固定、ズームなし
- 2人の距離（足元の中心どうし）は「画面幅 − 2 × 画面端の余白」までに制限する（余白は推奨 60px）。この制限は描画ではなく押し合いの処理（2.4 の5番目）で行う
- 画面揺れはカメラの位置に足すだけの描画上の効果。ロジックの位置は変えない

### 2.6 HUD

- 体力・タイマー・ラウンド勝利数・ゲージ・連続技の数は、対戦ロジックの状態を読んで描くだけ
- 体力バーの「赤く残ってからゆっくり縮む」部分は描画側だけが持つ見た目の値（ロジックには持たせない）

### 2.7 演出

- 演出は「出来事」と「キャラの状態」から作る。ロジックは演出のことを知らない
- ヒット火花・擬音文字・効果線・残像などは、描画側の「演出リスト」に足して、寿命が来たら消す
- 伸び縮み・揺れ・残像はキャラの状態（技の何フレーム目か、のけぞりの何フレーム目か）から計算する
- 2P の色違いは、画像の読み込み時に色味を変えた画像を別に作っておく（推奨（ユーザー未確定））。Canvas の `filter` は Safari での対応が不安定なため、毎フレームのフィルタ処理はしない
- KO のスローは、対戦シーンが対戦ロジックの更新を「2フレームに1回」にして表す

### 2.8 音

- 効果音は出来事ごとに鳴らす。技データに効果音の名前を書け、書いていなければ重さ（軽・中・重）ごとの共通の音を使う
- BGM はステージごと。ループ再生
- ブラウザは最初のキー入力まで音を出せないので、タイトル画面の最初の入力で音の準備をする
- 音量は全体・BGM・効果音の3つを共通設定に持つ（調整用。画面からは変えない）

### 2.9 CPU

- CPU は毎フレーム `InputFrame` を作るだけ。人と同じ入力の仕組みを通るので、CPU だけ特別に強い・ズルい動きはできない
- CPU が見るのは「何フレームか前の状態」（反応の速さ：やさしい 30F / ふつう 18F / つよい 10F）。直近の状態を一定フレーム分だけ記録しておき、遅れた状態で判断する
- 判断は簡単なルールの組み合わせ（距離が遠ければ近づく、相手の技が出始めたら確率でガード、届く距離なら技を出す、など）。難易度ごとの違いは数値だけにする
  - ガードの判断は、相手の技1つにつき1回だけ確率で決める（毎フレーム抽選すると確率が実質上がるため）
  - つよい：相手の空振りの硬直を見つけたら反撃する、ゲージ満タンなら超必殺を狙う
- 乱数は 2.4 と同じ種付き乱数を使う。同じ種なら CPU も同じ動きをするので、テストできる

## 3. ロジックと描画の分離

- 対戦ロジック（`src/logic/`）は Canvas・DOM・音・時刻に一切触れない。入力と状態を受け取って、次の状態と出来事を返すだけ
- これを仕組みで守るため、`src/logic/` だけ TypeScript の設定でブラウザの型（`window`・`document` など）を使えなくする。うっかり使うと型エラーになる
- テストでは、入力の列を与えて「何フレーム目に何が起きるか」を確かめる

```ts
// テストのイメージ（APIは仮）
// 1P のリンがジャブ、2P のゴンゾーは何もしない
const result = simulate({ p1: 'lin', p2: 'gonzo', seed: 1 }, inputs);
// 発生4 → 5F目に攻撃の箱が出る、当たればゴンゾーの体力は 1150 − 30
```

- テストの例
  - 各技の攻撃の箱が「発生＋1」フレーム目に出て、「発生＋持続」フレーム目まで残る
  - 連拳は5回当たり、合計90、補正なし。ジャブ → 連拳キャンセルなら連拳側に補正がかかる
  - 打撃同士が同じフレームで当たったら相打ち、1F ずれたら先に当てた方が勝つ
  - 掴まれてから 8F 以内の掴みで投げ抜け、9F 目では抜けられない
  - マッスルポーズが1発耐えて反撃パンチが出る。2発目は耐えない
  - 通常の必殺技の削りで体力が1で止まる。超必殺の削りでは KO する
  - 画面端でのノックバックが攻撃側に返る
  - すべてのキャラデータが型と整合している（下の「データの検査」）
- 描画・音・メニューは自動テストしない。開発用の表示（7章）を使って目で確かめる

## 5. キャラデータの形式

1キャラ＝1つの JSON ファイル（`src/data/characters/<キャラID>.json`）。JSON にしたのは、コードを読めなくても数値を直せて、ゲーム本体から切り離せるため（推奨（ユーザー未確定））。書き間違いは読み込み時の検査とテストで見つける。

### 型定義（例）

```ts
type Weight = 'light' | 'medium' | 'heavy';               // 軽・中・重
type Box = { x: number; y: number; w: number; h: number }; // 足元中心・右向き基準・上がプラス
type FrameRange = { from: number; to: number };            // 技の何フレーム目から何フレーム目まで（1始まり）

// 技を出す入力の枠。1つの枠に1つの技
type MoveSlot =
  | 'punch' | 'kick' | 'crouchPunch' | 'crouchKick' | 'grab'
  | 'special' | 'forwardSpecial' | 'downSpecial' | 'super'
  | 'airPunch' | 'airKick';

interface CharacterData {
  id: string;              // フォルダ名・ファイル名と同じ
  name: string;            // 表示名（リン）
  type: string;            // 表示用のタイプ（スピード型）
  order: number;           // キャラ選択での並び順
  stageId: string;         // ホームステージ
  stats: {
    health: number;            // 体力
    walkSpeed: number;         // 歩き速度 px/F
    jumpAirFrames: number;     // ジャンプの滞空時間 F
    jumpHeight: number;        // ジャンプの高さ px
    jumpForwardSpeed: number;  // 斜めジャンプの横速度 px/F
    armorDamageRate?: number;  // アーマーで耐えた時の被ダメージ割合（アーマー技を持つキャラだけ）
  };
  boxes: {
    push: { stand: Box; crouch: Box; air: Box };
    hurt: { stand: Box[]; crouch: Box[]; air: Box[] };
  };
  poses: Record<string, PoseData>;          // ポーズ名 → 画像
  moves: Record<MoveSlot, MoveData>;        // 入力に対応する技（全枠必須）
  subMoves?: Record<string, MoveData>;      // 入力では出ない派生技（マッスルポーズの反撃パンチなど）
  voice?: Record<string, string>;           // 勝利・KO などの効果音名（任意）
}

interface PoseData {
  image: string;                 // assets/ からの相対パス
  anchor: { x: number; y: number }; // 画像の中で「足元の中心」にあたる位置
}

interface MoveData {
  name: string;
  kind: 'normal' | 'special' | 'super' | 'throw' | 'commandThrow';
  pose: string;                  // 使うポーズ名（発生〜硬直を通して1枚）
  startup: number;               // 発生
  active: number;                // 持続
  recovery: number;              // 硬直
  hits?: HitData[];              // 打撃の当たり（多段なら複数）
  throw?: ThrowData;             // 掴み・コマンド投げのとき
  guardLock?: boolean;           // 1発ガードしたら残りもガード（連拳）
  cancelInto?: ('special')[];    // ヒット・ガード時にキャンセルできる先（通常技だけ）
  movement?: MoveStep[];         // 突進・上昇など
  invincible?: FrameRange[];     // 無敵（打撃も掴みも当たらない）
  armor?: ArmorData;
  hurtOverride?: { frames: FrameRange; boxes: Box[] }[]; // 食らいの箱の上書き
  air?: boolean;                 // 空中攻撃
  landingRecovery?: number;      // 着地の隙（省略時は共通値）
  meterCost?: number;            // 超必殺のゲージ消費
  cinematic?: string;            // ヒット後の演出の種類（"rush" など）
  sfx?: string;                  // 効果音名（省略時は重さごとの共通音）
}

interface HitData {
  frames?: FrameRange;   // 持続の中のどこで出るか（省略時は持続全体）。持続の1F目＝1
  damage: number;
  weight: Weight;
  box: Box;
  knockdown?: boolean;   // 当たると相手がダウン
  groundOnly?: boolean;  // 地上の相手にだけ当たる（ヒップドロップの衝撃波）
}

interface ThrowData {
  range: number;         // 掴み間合い px（押し合いの箱の前端どうしの隙間）
  damage: number;
  techable: boolean;     // 投げ抜けできるか
  end: 'front' | 'swap' | 'toWall'; // 投げ終わりの位置：相手の前 / 入れ替え / 画面端まで
  duration?: number;     // 投げ演出の長さ（省略時は共通値）
}

interface MoveStep { frames: FrameRange; dx: number; dy?: number } // その区間で合計いくつ動くか（等速）

interface ArmorData {
  frames: FrameRange;    // アーマーが付いている区間
  hits: number;          // 耐えられる回数
  onAbsorb?: string;     // 耐えたら移る派生技（subMoves の名前）
}
```

### 03_moves.md の各項目との対応

| 03 / 06 の項目 | データ上の表し方 |
|---|---|
| 発生・持続・硬直 | `startup`・`active`・`recovery`。全体は足し算で求め、データには書かない |
| ダメージ・重さ | `hits[].damage`・`hits[].weight`。多段は `hits` を複数並べる |
| ダウンする技（足払いなど） | `hits[].knockdown: true` |
| 突進（突進掌・ラリアット・百裂連拳の突進距離） | `movement`。距離は06の値をそのまま `dx` に書く |
| 無敵（昇り蹴り・百裂連拳） | `invincible` |
| アーマー（マッスルポーズ・ラリアット突進） | `armor`。被ダメージ割合はキャラの `stats.armorDamageRate` |
| マッスルポーズの反撃パンチ | `subMoves.muscleCounter` を作り、`armor.onAbsorb` で指定 |
| ヒップドロップの衝撃波 | 発生中の `movement` でジャンプ、`hits[].groundOnly: true` で左右 160px の箱 |
| 空中攻撃・着地の隙 | `air: true`、ドロップキックだけ `landingRecovery: 20` |
| 掴み・コマンド投げ | `throw`（間合い・投げ抜け可否・投げ終わりの位置） |
| 超必殺のゲージ消費・演出 | `meterCost`、`cinematic`（百裂連拳の乱打は `"rush"`） |
| キャンセル可否 | `cancelInto`（通常技に付ける） |
| ポーズ画像 | 技の `pose` → `poses` → 画像ファイル |

### フレームの数え方（重要）

- ボタンを押して技が始まったフレームを「技の1F目」とする
- 当たり判定が出るのは「発生＋1」F目から「発生＋持続」F目まで。硬直はその次から「全体」F目まで。全体F目の次のフレームから動ける
  - 例：ジャブ（発生4・持続2・硬直8）は 1〜4F目が発生、5〜6F目に攻撃の箱、7〜14F目が硬直、15F目から動ける
  - 03 の「全体＝発生＋持続＋硬直」と合う数え方にした。一般的な格ゲーの表記（発生に当たる1F目を含める）とは1F ずれるので注意（推奨（ユーザー未確定））
- 無敵・アーマー・突進の区間（`FrameRange`）は「技の何F目か」で書く。昇り蹴りの無敵 1〜7F は技の1〜7F目
- 多段ヒットの `hits[].frames` だけは「持続の何F目か」で書く（持続の1F目＝技の発生＋1F目）。持続の長さを変えたときに直しやすいため

### ポーズと演出

- 1つの技は発生〜硬直まで同じポーズ画像を使う（`02_characters.md`「状態ごとに1枚」）。発生中は縮め、持続中は伸ばす、などの動きは描画側が技の何F目かを見て付ける
- 必要なポーズ名（待機・歩き・ジャンプ・しゃがみ・ガード・被弾・ダウン・勝利・カットイン・立ち絵など）は共通の一覧で決めておき、検査で全部揃っているか確かめる

### 演出の種類について

- `cinematic`（乱打・投げの振り回しなど）と投げ終わりの位置（`end`）は、コード側に用意した種類から選ぶ。新キャラは既存の種類を組み合わせれば、コードを変えずに追加できる
- まったく新しい種類の演出が欲しいときだけ、描画とロジックに種類を1つ足す（これはコード変更になる）

### データの検査

- 読み込み時に、必須項目の有無、数値の範囲（フレームが1以上など）、ポーズ名・派生技名・ステージ名の参照先があるか、画像ファイル名の形を確かめる。おかしければ画面にエラーを出して止める（黙って動かない）
- 同じ検査をテストでも全キャラ分行う

### 新キャラを追加する手順

1. 画像を用意して `assets/images/characters/<キャラID>/` に置く（必要なポーズと命名は `07_assets.md`）
2. `src/data/characters/<キャラID>.json` を作る。既存キャラのファイルをコピーして書き換えるのが早い
3. ステージも増やすなら 背景画像 `assets/images/stages/stage_場所.jpg` と `src/data/stages/<ステージID>.json` を作る
4. `npm test` でデータの検査を通す
5. `npm run dev` で起動し、開発用表示で箱の位置と大きさを画像に合わせる
6. `03_moves.md`（技表）と `06_params.md`（キャラ別の値）に新キャラの節を足す

コード（`src/` の `.ts`）は触らない。キャラ選択の並びにも自動で加わる。

| 歩き速度・ジャンプの滞空時間・体力 | キャラデータの `stats` |
| 掴み間合い | 掴み技の `throw.range` |
| 突進距離・無敵・衝撃波の範囲・反撃パンチ・ドロップキックの着地の隙 | キャラデータの各技 |
| アーマーで耐えた時の被ダメージ | キャラデータの `stats.armorDamageRate` |

## 7. 実装時の取り決め

迷いやすい点を先に決めておく。上の章と重なるものは要点だけ再掲する。

- **数え方**：技の1F目＝ボタンを押したフレーム。攻撃の箱は「発生＋1」F目から（5章）
- **同じフレームは同時に処理**：1P と 2P の判定は同じ位置・同じ状態から計算し、結果はあとでまとめて反映する。処理の順番で 1P が有利になってはいけない
- **判定の優先順位**：無敵 → 掴めない状態 → 両者同時（相打ち・超必殺・アーマー・打撃対掴み）→ 掴み → アーマー → ガード → ヒット（2.4）
- **ガードの条件**：地上で、ガードボタンを押していて、動ける状態かガード硬直中。向きは関係ない（上下段・めくりなし）。ガード中は歩けない
- **攻撃とガードの同時押し**：攻撃ボタンが優先（ガードを押したまま攻撃ボタンを押すと技が出る）。必殺＋ガードの同時押し（3F 以内）だけは超必殺
- **地上の同時入力**：同じフレームならジャンプより攻撃を優先
- **ヒットストップ**：当てた側・食らった側の両方が止まる（相打ちも同じ）。止まっている間も入力はバッファに入る
- **押し合い**：押し合いの箱が重なったら半分ずつ離す。片方が画面端なら、もう片方が全部動く。着地して重なったときは、中心が相手より左にいる方を左へ出す（同じ位置ならステージの中央から遠い方を内側へ）
- **飛び越え**：空中の押し合いの箱は地上より小さく高い位置にし、相手の上を通れるようにする（大きさは箱の調整で決める）
- **振り向き**：技・のけぞり・空中の途中では振り向かない（2.4）
- **投げのダメージ**：投げ演出の最後に与える。投げ演出中に KO になることはない
- **整数**：体力・ダメージ・ゲージは整数。計算の端数は切り捨て。位置は小数でもよい
- **同じ結果の再現**：ロジックは種付き乱数だけを使う。同じ設定・同じ入力なら毎回同じ結果になる（テストと不具合の再現のため）
- **開発用表示**（開発ビルドだけ。本番には入れない。キーは推奨）
  - F1：判定の箱を色分けして表示（押し合い・食らい・攻撃・掴み）
  - F2：1フレームずつ進めるモード（F3 で1F進む）
  - F4：両者の状態名・技の何F目か・有利フレームを表示
- **データのエラー**：キャラデータの間違いは起動時に止めて画面に表示する。直さずに動かし続けない
