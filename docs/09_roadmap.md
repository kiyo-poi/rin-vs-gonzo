# 09 作る順番（ロードマップ）

何をどの順で作り、どうなったら「できた」とするかをまとめる。
前提は `01`〜`06`。数値は `03_moves.md`（技）と `06_params.md`（調整値）を正とし、ここでは確認の仕方だけ書く。

## 基本方針：四角で面白さを先に確かめる

- M1〜M3 はキャラを色つきの四角（体の箱・攻撃の箱）だけで作る。画像と音は M5 まで入れない
- 理由
  - 格闘ゲームの面白さは「発生・硬直・間合い・三すくみ」でほぼ決まり、見た目では直せない。先に四角で遊んで、つまらなければ数値や技を直す
  - 画像は AI 生成で1キャラ約22枚と手間が大きい。技の中身が固まる前に作ると、技の変更で描き直しになる
  - 四角なら当たり判定がそのまま見えるので、「当たった／当たっていない」の確認がしやすい
  - 当たり判定の大きさは画像ができてから合わせる（`open-questions.md`）。それまでは四角の仮の大きさで進める

## マイルストーン一覧

| # | 名前 | ひとことで | 見た目 |
|---|---|---|---|
| M1 | 四角で動く試作 | 2人で四角を動かして殴り合える | 四角 |
| M2 | 対戦ルール | 1試合が最初から最後まで成立する | 四角 |
| M3 | 全技 | 2キャラの全技が仕様どおりに出る | 四角 |
| M4 | 画面の流れ | タイトルから結果まで通しで遊べる | 四角＋仮の文字 |
| M5 | 画像と音 | 見た目と音が入って「ゲームらしく」なる | 本番 |
| M6 | CPU | 1人で3難易度と遊べる | 本番 |
| M7 | 調整と公開 | 数値を詰めて URL で誰でも遊べる | 本番 |

- 1つのマイルストーンは「完成条件」を満たしたら終わり。確認項目が全部通るまで次に進まない
- 並行してよい作業
  - M3 の技が固まったら、M5 用の画像生成と、効果音・BGM の素材探し・ライセンス確認を並行で始めてよい
  - 公開先には M1 の時点で一度、空に近いページを置いて「URL で開ける」ことを確かめておく（最後に公開でつまずかないため）

## 開発用の道具（全マイルストーン共通）

遊んで確認するための道具。公開版では表示しない。

- 当たり判定の表示：体の箱・攻撃の箱・掴みの範囲を色分けで表示する
- フレーム表示：今が技の「発生中／持続中／硬直中」か、何フレーム目かを表示する
- コマ送り：一時停止して1Fずつ進める
- キー表示：今押されているキーを1P・2P別に表示する（同時押しの取りこぼし確認用）
- 数値の即時変更：`06_params.md` の値を、再読み込みだけで差し替えて試せるようにする

## M1 四角で動く試作

移動・ジャンプ・しゃがみ・ガード・パンチだけを、2人で操作できるようにする。

### 作るもの

- 1280×720 の画面に、地面と2つの四角（1P・2P）
- 60fps のフレーム単位で進む土台（重い処理があっても1F＝1/60秒の進み方を崩さない）
- 左右移動、ジャンプ（↑）、しゃがみ（↓）、ガード（押している間）
- パンチ1種だけ（キャラ差なし、リンのジャブの数値で仮置き）
- 当たり判定（攻撃の箱が相手の体の箱に重なったらヒット）と体力の減少
- 1P・2P のキー入力（`04_system.md` の仮配置。2P はテンキーと J〜, の両方）

### 完成条件

- 2人で1台のキーボードを使い、四角を動かしてパンチを当て合い、体力を減らせる
- ガードを押していればパンチでは体力が減らない

### 確認項目

| 確認すること | 基準 | 方法 |
|---|---|---|
| パンチの発生 | ボタンを押して 4F目に攻撃の箱が出る（ジャブ：発生4） | 自動 |
| パンチの全体 | 14F で次の行動ができる（発生4＋持続2＋硬直8） | 自動 |
| ダメージ | 当たると体力が 30 減る | 自動 |
| ガード | ガード中に当たっても体力が減らない | 自動 |
| 歩き速度 | 仮の値（5px/F）で1Fごとに一定距離進む | 自動 |
| ジャンプ | ↑で跳んで、決めた滞空時間（仮 36F）で着地する | 自動 |
| 同時押し | 1P が「→＋↑＋パンチ」、2P が「←＋ガード＋テンキー4」を同時に押し続けても、両者の全キーが反応する | 手動（実機） |
| 同時押し（多め） | 1P・2P で合計8キー前後を同時に押して、取りこぼすキーがないか。取りこぼしたら組み合わせを記録 | 手動（実機） |
| テンキーなし | 2P を J K L M , で操作してもテンキーと同じに動く | 手動 |
| 手触り | 押してから動くまでに遅れを感じない | 手動 |

- 同時押しで取りこぼしが出たら、この時点でキー配置を見直して `04_system.md` を確定する（`open-questions.md` の「キー配置の確定」を閉じる）

### この段階で調整する `06_params.md` の値

- リン・ゴンゾーの歩き速度、ジャンプの滞空時間（キャラ差はまだ入れず、まず「気持ちよく動くか」を見る）

## M2 対戦ルール

1試合（ラウンド制）が最初から最後まで成立するようにする。技はまだパンチ＋キックくらいでよい。

### 作るもの

- ラウンド制（2ラウンド先取、1ラウンド99秒、最大5ラウンド）、タイマー、勝敗判定
- 時間切れ・同時KO・引き分けの扱い（`01_concept.md`）
- 押し合い（重ならない、歩いて押すと相手を少し押せる）、飛び越えて裏に回る、向きの自動切り替え
- 画面端とカメラ（ステージ 1920px、カメラは2人の中間を追う、2人の距離は最大 1280px）
- のけぞり・ガード硬直（軽・中・重）、ノックバック、画面端での押し返し
- 仮の HUD（体力・タイマー・勝利数を文字で出すだけでよい）

### 完成条件

- 2人で1試合を最後まで遊べて、勝者が表示される
- 画面端に追い詰めて殴っても、攻めた側が少しずつ下がり、永久に殴り続けられない

### 確認項目

| 確認すること | 基準 | 方法 |
|---|---|---|
| タイマー | 99 から1秒（60F）ごとに減り、0 で時間切れ | 自動 |
| 時間切れ | 体力が多い方の勝ち。同じなら両者に1勝 | 自動 |
| 同時KO | 両者に1勝。両者リーチなら最終ラウンドへ | 自動 |
| 最大ラウンド | 5ラウンドで決まらなければ引き分けで終わる | 自動 |
| のけぞり | 軽 / 中 / 重 がそれぞれ 14 / 18 / 24F 動けない | 自動 |
| ガード硬直 | 軽 / 中 / 重 がそれぞれ 10 / 13 / 17F 動けない | 自動 |
| ノックバック | ヒットで 20 / 35 / 60px、ガードではその 1.2 倍下がる | 自動 |
| 画面端 | 端の相手を殴ると、下がれない分だけ攻めた側が下がる | 自動 |
| 押し合い | 歩いて押すと相手が歩き速度の 50% で押される。2人が重ならない | 自動 |
| 距離の上限 | 2人の距離が 1280px を超えない。カメラがステージ外を映さない | 自動 |
| 向き | 飛び越えると着地後に相手の方を向く。空中・技の途中では振り向かない | 自動 |
| テンポ | 1ラウンドの長さ、のけぞりの長さが「だれない」か | 手動 |

### この段階で調整する `06_params.md` の値

- ヒットのけぞり（軽・中・重）、ガード硬直（軽・中・重）
- ノックバック距離（軽・中・重）、歩きで相手を押す速さ

## M3 全技

2キャラの全技を、四角のまま仕様どおりに入れる。ここで「対戦として面白いか」を判断する。

### 作るもの

- `03_moves.md` の全技（リン 11、ゴンゾー 11）。キャラはデータで定義する
- 掴みと投げ、投げ抜け、打撃・ガード・掴みの三すくみ
- 必殺技3種、キャンセル（通常技 → 必殺技）、連続技のダメージ補正、コンボ数の表示（文字だけ）
- 削り（必殺技は体力1で止まる、超必殺はKOできる）
- アーマー、無敵（昇り蹴り・百裂連拳フィナーレ・起き上がり）、相打ち
- ダウンと起き上がり、空中攻撃（1ジャンプ1回、着地の隙）
- ゲージ（溜まり方、満タンで光る代わりの表示、ラウンド持ち越し）と超必殺（暗転は画面を止めるだけでよい）

### 完成条件

- 2人で全技を出し合って1試合遊べる
- 「リンは手数で攻め、ゴンゾーは掴みとアーマーで押し返す」という違いが四角でも感じられる
- どちらかのキャラが一方的に勝ちすぎない（2人で数試合して極端な偏りがない）

### 確認項目

| 確認すること | 基準 | 方法 |
|---|---|---|
| 全技の発生・持続・硬直 | 22技すべてが `03_moves.md` の表どおり | 自動 |
| 全技のダメージ | 単発で当てた時に表どおり減る | 自動 |
| 連拳 | 7F目から 4F ごとに計5ヒット、合計 90。1発ガードしたら最後までガードが続く | 自動 |
| キャンセル | 通常技の硬直中に必殺技を入力すると、硬直を打ち消して必殺技が出る（ヒット時・ガード時とも） | 自動 |
| キャンセルできないもの | 必殺技 → 超必殺は繋がらない | 自動 |
| ダメージ補正 | キャンセルで繋いだ2発目以降が 80%（例：ジャブ→突進掌で 30＋56＝86） | 自動 |
| 三すくみ | 掴みはガード中の相手を掴める。掴みの発生前に打撃が当たれば打撃が勝つ | 自動 |
| 投げ抜け | 掴まれてから 8F 以内に掴みボタンで両者弾かれる。9F 目以降は投げられる | 自動 |
| 投げ抜け不可 | ジャイアントスイングは投げ抜けできない | 自動 |
| 空中の相手 | 掴み・ジャイアントスイングはジャンプ中の相手を掴めない | 自動 |
| 削り | 必殺技をガードさせると本来の 20% が減る。体力1では止まる。超必殺の削りではKOする | 自動 |
| アーマー | マッスルポーズ・ラリアット突進は打撃を1発だけ耐え、被ダメージは 50%。掴みは耐えられない | 自動 |
| マッスルポーズの反撃 | 耐えたら反撃パンチ（発生8F・100）が出る | 自動 |
| 無敵 | 昇り蹴りは 1〜7F、起き上がりは 6F、打撃が当たらない | 自動 |
| 相打ち | 打撃同士が同じFで当たると両者ダメージなし、両者 16F 動けない。超必殺は一方的に勝つ。超必殺同士は弾かれ、ゲージは消費される | 自動 |
| ダウン | 足払い・ローキック払い・投げでダウンし、40F で起き上がる | 自動 |
| 空中攻撃 | 1回のジャンプで1回だけ。着地の隙は 4F（ドロップキックだけ 20F） | 自動 |
| ヒップドロップ | 衝撃波は地上の相手だけに当たる（左右 160px） | 自動 |
| ゲージ | 当てた側は与ダメージの 0.8 倍、食らった側 0.4 倍、ガードさせた側 0.3 倍溜まる。1000 で満タン、超必殺で 0。次のラウンドに持ち越す | 自動 |
| 超必殺の暗転 | 30F 全体が止まる。止まっている間はタイマーも減らない | 自動 |
| ゲージの溜まる速さ | 普通に戦って約50秒で満タンになるか | 手動 |
| 面白さ | 差し返し（下がって空振りに当てる）、三すくみの読み合いが起きるか | 手動 |
| キャラ差 | リンの速さ・ゴンゾーの重さが四角でも伝わるか | 手動 |

- 面白さの確認で「つまらない」となったら、M4 に進まずに技・数値を直す。必要なら `02`・`03` を書き換える

### この段階で調整する `06_params.md` の値

- 連続技のダメージ補正、ゲージ増加量、削りの割合、投げ抜けの受付時間
- ダウン〜起き上がり、起き上がりの無敵、空中攻撃の着地の隙、相打ちの硬直、超必殺の暗転時間
- リン：掴み間合い、突進掌・百裂連拳フィナーレの突進距離、昇り蹴り・百裂連拳フィナーレの無敵
- ゴンゾー：掴み間合い（ボディスラム・ジャイアントスイング）、マッスルポーズの反撃パンチ、アーマーの被ダメージ、ラリアット突進の距離、ヒップドロップの範囲、ドロップキックの着地の隙

## M4 画面の流れ

タイトルから結果まで、ゲームとして通しで遊べるようにする。見た目はまだ四角と仮の文字でよい。

### 作るもの

- タイトル → モード選択（2人対戦 / CPU戦＋難易度）→ キャラ選択 → 対戦 → 結果（再戦 / キャラ選択へ / タイトルへ）
- ポーズ（Esc。再開 / キャラ選択へ / タイトルへ）
- キー配置と技一覧の表示（タイトル・キャラ選択・ポーズ）
- 本番の形の HUD（体力バーの赤い残り、タイマー、勝利数の●、ゲージ、「2 HIT」）
- 対戦中の演出（ROUND 1 → FIGHT!、ヒットストップ、火花、擬音文字、画面の揺れ、K.O. のスロー、TIME UP、DRAW、決着表示）。画像がなくても出せるものだけ
- CPU戦は M6 までは「動かない相手」で仮置き

### 完成条件

- 説明なしで、初めての人がタイトルから1試合を終えて、もう一度遊ぶところまで迷わず進める

### 確認項目

| 確認すること | 基準 | 方法 |
|---|---|---|
| 画面の行き来 | `01_concept.md` の流れどおりに全画面へ行けて、戻れる | 自動＋手動 |
| メニュー操作 | 方向キーで移動、パンチで決定、ガードで戻る。タイトル・モード選択・結果は 1P・2P どちらでも操作できる | 手動 |
| キャラ選択 | 1P・2P が同時に選べる。同キャラを選べる。CPU戦では CPU のキャラがランダム | 手動 |
| キャラの追加 | キャラデータを1つ足すと、選択肢が自動で増える | 自動 |
| ポーズ | どちらの Esc でも止まり、止まっている間はタイマー・キャラが1Fも進まない | 自動 |
| ラウンド開始 | ROUND 1 → FIGHT! の約2秒間は動けない | 自動 |
| ヒットストップ | ヒットした瞬間に 6F 止まる | 自動 |
| HUD | 体力バーの減った分が赤く残ってから縮む。ゲージ満タンで光る。キャンセルが繋がると「2 HIT」 | 手動 |
| 演出のテンポ | 演出が長すぎてテンポが落ちないか | 手動 |

### この段階で調整する `06_params.md` の値

- ヒットストップ、掴み成立〜投げ終わりの演出時間、超必殺の暗転時間（演出を乗せたうえで見直す）
- ラウンド開始・KO のスローなどの演出時間（`06_params.md` にまだ値がない。`open-questions.md` 参照）

## M5 画像と音

四角を AI 生成の画像に差し替え、効果音・BGM・ステージを入れる。

### 作るもの

- キャラ画像（1キャラ約22枚、`02_characters.md` のポーズ一覧）と、伸び縮み・残像・効果線・揺れの演出
- 2P の色違い（色味フィルタ）、超必殺のカットイン（顔アップ）、キャラ選択の立ち絵、勝利ポーズ
- 当たり判定の大きさを画像に合わせて決める（`open-questions.md` の「当たり判定の大きさ」を閉じる）
- ステージ2つ（リン：中華街、ゴンゾー：プロレスのリング）。2P 側（CPU戦では CPU）のキャラのステージを使う
- 効果音・BGM（無料素材。ライセンスを確認し、必要ならクレジットを表示）

### 完成条件

- 四角だった M4 の状態が、すべて画像と音に置き換わり、遊び心地は M4 から変わっていない

### 確認項目

| 確認すること | 基準 | 方法 |
|---|---|---|
| ポーズの抜け | どの状態でも対応する画像が出る（画像のない状態がない） | 自動 |
| 判定の見た目 | 当たり判定の表示を重ねて、画像と箱が大きくずれていない | 手動 |
| 手触りが変わらない | 画像を入れても技のフレーム数が変わっていない（M3 の自動テストがそのまま通る） | 自動 |
| 同キャラ対戦 | 2P が色違いで、ひと目で区別できる | 手動 |
| 処理の重さ | 演出が多い場面（超必殺・連拳）でも 60fps を保つ | 手動 |
| 音 | ヒット・ガード・相打ち・投げ抜け・超必殺・KO で音が鳴る。BGM がループする | 手動 |
| ライセンス | 使う素材すべての利用規約を確認し、記録してある | 手動 |

### この段階で調整する `06_params.md` の値

- ヒットストップ（画像と音が入ると手応えの感じ方が変わるので見直す）
- 当たり判定の大きさ（`06_params.md` ではなくキャラデータに置く）

## M6 CPU

1人で CPU と3難易度で遊べるようにする。

### 作るもの

- CPU（やさしい / ふつう / つよい）。CPU は人と同じ「キー入力」を作って操作する（人にできないことはさせない）
- 反応の速さ、ガード確率、必殺・超必殺の使い方の違い（`04_system.md`）

### 完成条件

- 初めての人が「やさしい」に勝てる。慣れた人でも「つよい」には手応えがある

### 確認項目

| 確認すること | 基準 | 方法 |
|---|---|---|
| 反応の速さ | 相手の行動を見てから 30 / 18 / 10F 後に動き出す | 自動 |
| ガード確率 | 多数回の打撃に対し、20 / 50 / 80% 前後でガードする | 自動（多数回試して割合を見る） |
| 超必殺 | つよいはゲージ満タンで超必殺を狙う。やさしいはほとんど使わない | 自動＋手動 |
| 空振りへの反撃 | つよいは、こちらの空振りに反撃してくる | 手動 |
| 動きが止まらない | CPU 同士を長時間戦わせて、固まる・画面端でハマる等がない | 自動 |
| 難易度の差 | 3段階の違いがはっきり感じられる | 手動 |

### この段階で調整する `06_params.md` の値

- CPU の反応の速さ、CPU のガード確率（3難易度とも）

## M7 調整と公開

数値を詰めて、URL で誰でも遊べるようにする。

### 作るもの

- `06_params.md` 全体の最終調整（候補の幅の中で）。決まった値は `06_params.md` の初期値を書き換える
- 対応ブラウザでの動作確認
- 公開（GitHub Pages または Cloudflare Pages）

### 完成条件

- 公開 URL を開くだけで、PC のブラウザで最後まで遊べる
- `open-questions.md` に、公開を止めるような未決事項が残っていない

### 確認項目

| 確認すること | 基準 | 方法 |
|---|---|---|

## 手動で確認するもの・自動テストで確認するもの

### 方針

- 「何フレーム目に何が起きるか」が決まっているものは自動テストにする
  - 例：発生・持続・硬直、ダメージ、のけぞり・ガード硬直の長さ、補正、削り、投げ抜けの受付、無敵、ゲージ量、ラウンドの勝敗
  - 仕様書に数値があるものは、基本的にすべて自動テストで確かめる
- 「気持ちいいか・面白いか・見やすいか」は手動で遊んで確かめる
  - 例：手触り、テンポ、キャラ差、演出の長さ、難易度の差、画像と判定のずれ
- 実機・環境に依存するものは手動
  - 例：キーボードの同時押し、ブラウザごとの動作、60fps を保てるか

### 自動テストの書き方の考え方

- 「この入力をこのフレームに押す」という入力の列を与えて、何フレーム後にどうなっているかを確かめる形にする
- そのため、ゲームの中身（キャラの動き・判定・ルール）は、画面に描かなくても1Fずつ進められるように作る（作り方の詳細は `08_architecture.md` に合わせる）
- 同じ入力なら必ず同じ結果になるようにする（乱数を使う CPU も、乱数の種を固定すればテストで同じ動きを再現できる）
- `06_params.md` の値を変えたときにテストが壊れにくいよう、テストは数値を直接書かず、調整値を読んで期待値を出す
- 自動テストはマイルストーンごとに増やし、前のマイルストーンのテストは消さずに毎回すべて流す

### 手動確認のやり方

- 各マイルストーンの終わりに、確認項目の「手動」の行を上から実際に遊んで確かめる
- 2人対戦の確認は2人で行う（1人で両手を使うと同時押しの確認にならない）
- 「手触り」で数値を変えたら、変えた値と理由を `06_params.md` のメモに残す
